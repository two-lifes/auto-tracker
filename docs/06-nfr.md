# 06. Нефункциональные требования

## Безопасность
- Токен бота и белый список ID хранятся в переменных окружения или файле конфигурации вне репозитория. В репозиторий кладётся только пример без значений.
- Бот принимает обновления только от владельца (FR-1).
- Бот работает под отдельным непривилегированным пользователем ОС. Каталог данных доступен только ему.
- Для получения обновлений используется long polling: не нужны домен, TLS и открытые входящие порты.

## Надёжность
- Автоматический запуск при старте сервера и перезапуск при падении.
- Состояния диалогов и задания напоминаний хранятся постоянно и переживают перезапуск.
- Напоминания, пропущенные во время простоя, отправляются после старта (US-12), без дублей.
- Ошибка одного запроса не роняет бота: владельцу уходит короткое сообщение, подробности пишутся в лог.

## Хранение фото
- Для каждого фото сохраняются идентификатор файла Telegram (для быстрой повторной отправки) **и** локальная копия на VPS (на случай, если идентификатор станет недействительным).
- Каталоги упорядочены по профилю и записи или метке. Имена файлов уникальны.
- Ограничения Telegram Bot API (проверить по актуальной документации core.telegram.org/bots/api на старте реализации):
  - скачать файл ботом можно, только если он не больше 20 МБ;
  - отправить фото можно размером до 10 МБ, документ до 50 МБ;
  - альбом содержит от 2 до 10 элементов.
- Фото, присланное как «фото», Telegram сжимает. Для оригинала владелец отправляет файл. Это написано в справке бота.

## Резервное копирование
- Ежедневный бэкап БД и фото. Хранение: 7 ежедневных и 4 еженедельных копии.
- Копия БД снимается согласованно, без риска получить повреждённый файл во время записи.
- Обязательна копия за пределами VPS (другой сервер, облачное хранилище или отправка архива БД владельцу в Telegram, если размер позволяет).
- Процедура восстановления описана пошагово и проверена хотя бы раз (US-16).
- Владелец получает уведомление, если бэкап не удался.

## Производительность
- Ответ на действие приходит в пределах 1–2 секунд, если отправка файлов не требуется.
- Отправка сообщений соблюдает лимиты Telegram (не больше примерно одного сообщения в секунду в чат), альбомы и массовые выдачи идут с паузами.

## Данные и время
- Часовой пояс владельца задаётся в настройках, все расписания считаются в нём.
- Изменения схемы БД делаются только версионированными миграциями, без потери существующих данных.

## Логи и наблюдаемость
- Логи с ротацией и ограничением объёма. Токен и содержимое фото в логах не появляются.
- Простая проверка «жив ли бот», например служебная команда со статусом: версия, время работы, дата последнего бэкапа.

## Сопровождение
- Автотесты на бизнес-правила модели данных (раздел «Бизнес-правила» в 04) и на расчёт напоминаний.
- Линтер и форматтер, их проверка обязательна перед завершением этапа.
- Инструкция по развёртыванию и обновлению на VPS в README репозитория.
