# Журнал решений

Формат: номер, дата, решение, причина, статус (принято / предложено / заменено).

## D-1. Профиль использования = профиль автомобиля (2026-10-20, принято)
Каждый автомобиль имеет свой профиль со своими записями, пробегом, фото и напоминаниями. Активный профиль задаёт контекст всех действий.
Причина: требование владельца — сейчас одна машина, в будущем больше.

## D-2. Напоминания задаёт сам владелец, в гибкой форме (2026-10-20, принято)
Условия по дате, пробегу, интервалу и «что наступит раньше», с предупреждениями и шаблонами (FR-7).
Причина: требование владельца.

## D-3. Размещение на собственном VPS владельца (2026-10-20, принято)
Получение обновлений через long polling.
Причина: требование владельца. Long polling не требует домена и TLS.

## D-4. Стек: Python + aiogram 3 + SQLite (2026-10-20, принято)
Подробности в `07-stack.md`. Конкретно: Python 3.12, aiogram 3, SQLAlchemy 2 async + aiosqlite, Alembic, pytest, ruff; версии закреплены в `pyproject.toml`.
Причина: подтверждено владельцем на этапе 0, тот же стек у его других ботов (`bot-template/`).

## D-5. Фото хранятся дважды: идентификатор Telegram и локальная копия (2026-10-20, предложено)
Причина: быстрая повторная отправка плюс независимость от Telegram при восстановлении.

## D-6. Развёртывание: Docker Compose + CI/CD из шаблона (2026-10-20, принято)
Тот же VPS, что у других ботов владельца. GitHub Actions (тесты в Docker) → образ в GHCR `ghcr.io/two-lifes/auto_tracker` → SSH → `deploy/deploy.sh` в `/opt/auto_tracker`: копия БД перед стартом, ожидание "Run polling", автооткат. Автозапуск: `restart: unless-stopped` + Docker при загрузке. Логи: json-file, 3 × 10 МБ.
Причина: выбор владельца, схема проверена на соседних ботах.

## D-7. Белый список — список ID, посторонним молчание (2026-10-20, принято)
`ALLOWED_USER_IDS` через запятую (сейчас один ID). Обновления от остальных отбрасываются до обращения к БД и пишутся в лог, ответа нет (FR-1.2 допускает оба варианта).
Причина: формулировка FR-1.1 («белый список»); молчание не подтверждает постороннему, что бот живой.

## D-8. Уведомления о новой версии (2026-10-20, принято)
Таблица `deployments`, при старте записывается версия (git sha из образа) или откат (`FAILED_VERSION`), планировщик отправляет владельцу «🔄 Бот обновлён до версии …» / «⚠️ … не запустилось». История обновлений в настройках — на этапе 7.
Причина: решение владельца, из `bot-template/03`.

## D-9. Служебный статус — команда /status (2026-10-20, принято)
Версия, время работы, последний бэкап (до этапа 4 — «нет данных»). Не показывается в меню и в списке команд Telegram.
Причина: решение владельца; в списке команд 05 служебной команды нет.

## D-10. Состояние диалогов на этапе 0 — в памяти (2026-10-20, принято)
На этапе 0 диалогов нет; постоянное хранение FSM — объём этапа 1 по `08-roadmap.md`.

## D-11. Каталог данных и имя БД (2026-10-20, принято)
Переменная `DATA_DIR` (по умолчанию `data`, в контейнере `/data`), БД — `DATA_DIR/auto_tracker.db`. Фото и бэкапы будут в том же каталоге.
Причина: `07-stack.md` требует один каталог данных в конфигурации; вместо `DB_PATH` из шаблона.
