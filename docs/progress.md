### Этап 0. Каркас и развёртывание
Сделано:
- Каркас по `bot-template/`: конфиг из `.env` (`bot/config.py`), миграции Alembic при старте, сессия БД на апдейт под общим `db_lock`, обработчик ошибок («Что-то пошло не так…» + лог), планировщик раз в 60 с.
- FR-1: белый список `ALLOWED_USER_IDS`, посторонние игнорируются и пишутся в лог (D-7).
- /start (регистрирует владельца), /menu, /help, /cancel, /status (D-9); главное меню — 7 кнопок по 05, все пока отвечают «Раздел появится в следующих версиях.»; ответ на непонятный ввод и устаревшие кнопки.
- Уведомления о версиях (D-8).
- Docker (стадии base/test/runtime), локальный и прод compose с ротацией логов, `deploy/deploy.sh` с бэкапом БД и откатом, GitHub Actions (D-6).
- README: запуск, первичная настройка сервера и GitHub, обновление, эксплуатация.
- Тесты: whitelist, команды, меню, /cancel, ошибки, кнопки на недоступных сообщениях, записи версий, доставка уведомлений один раз и повтор после сетевой ошибки, конфиг.

Отклонения от документов:
- Строки «🚗 <профиль> · <пробег> км» над меню нет: профилей до этапа 1 нет.
- FR-2.6 (предложение создать профиль при первом запуске) — этап 1; сейчас /start показывает приветствие и меню.
- Сообщение владельцу о критических ошибках (FR-10.2) не реализовано (этап 7); ошибка обработки апдейта сообщается в ответ на сам запрос.

Известные ограничения:
- Локально тесты гонялись на Python 3.14 (3.12 не установлен), на 3.12 — в Docker.

Проверка владельцем: доступ только владельцу, команды и меню, деплой через CI с уведомлением о версии, автозапуск после перезагрузки VPS.
